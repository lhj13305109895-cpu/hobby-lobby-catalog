# 微信原生小程序

源码：`src/miniprogram/`。生成目录：`miniprogram/`（自动生成，不提交 Git）。

执行 `npm run build:miniprogram` 同步当前网站商品、系列、容量及装箱量，小程序不展示或导出价格；执行 `npm run test:miniprogram` 检查目录、编号搜索、容量装箱量、选款存储和分享路径。

没有 npm 命令的环境可直接执行 `node scripts/build-miniprogram.mjs` 和 `node --test tests/miniprogram.test.cjs`。

- 沿用网站真实企业微信和联系名片图片，支持长按图片及高清预览。

## 导入与上线

1. 在微信开发者工具中导入本仓库的 `miniprogram` 目录，选择小程序项目。默认 `touristappid` 仅供本地体验，不能用于正式预览或发布。
2. 正式使用时，在开发者工具中更换为自己的小程序 AppID。不要改生成目录里的业务源码；业务修改应在 `src/miniprogram/` 后重新构建。真实 AppID 可保存在本地 `src/miniprogram/project.private.config.json`，该文件已被 Git 忽略，构建时会复制到生成目录。
3. 当前图片域名是 `https://hobby-lobby-catalog.pages.dev`。用户在 2026-11-17 提供了微信后台截图，显示该地址已经保存到 `downloadFile` 合法域名。以后台实际保存结果为准，不能将域名保存成功等同于真机下载验证。开发工具刷新域名设置后重新编译和生成预览。缩略图、详情原图和导出 JPEG 必须已发布到网站；本地新增但未部署的图片不会自动出现在服务器。型号按钮的三张透明 PNG 仍随小程序打包。
4. 真机检查图片、长按预览、容量选择、退出重进持久化、分享单品和联系名片，再通过微信后台提交审核、发布。小程序主体、类目、隐私声明及备案等按平台后台要求补齐。

本版目录随构建打包，网站上新后需要重新生成并上传小程序版本，同时将新生成的导出 JPEG 发布到网站。照片准备脚本需要 Python + Pillow，可通过 `MINIPROGRAM_PYTHON` 指定解释器，默认优先使用本机 Codex 捆绑运行时。构建检查主包小于 1.5 MB、各分包小于 2 MiB 和整体保守 20 MiB 上限，并保留导入目录中已经配置的 AppID 及私有开发工具配置。选款仅保存在当前设备，不是订单，不跨设备同步；导出清单后由用户主动分享。没有接入支付、账户、后台下单，也没有提交小程序审核或发布。

`src/miniprogram/config.js` 中的 `exportPhotoSource` 默认为 `website`；需要回退时可设为 `local`，或通过 `MINIPROGRAM_EXPORT_PHOTO_SOURCE=local` 临时构建照片分包版。网站版不会打包导出 JPEG，首次导出新照片需要网络。照片路径带内容哈希，更新照片不会误用旧缓存。`node scripts/check-miniprogram-downloads.mjs --wait` 会等待网站资源就绪，并检查全部照片的 HTTP 状态、JPEG Content-Type、实际字节与哈希。

手机列表和选款卡片使用独立的 360px JPEG 缩略图，生成脚本为 `scripts/prepare-miniprogram-thumbnails.py`，清单为生成目录内的 `data/thumbnails.js`；`optimizedThumbnails` 控制是否使用。缩略图由网站提供，不打包进小程序；商品详情和点击预览继续使用原高清图片。首次只创建 24 张商品卡片，向下滚动自动追加，保留跨系列连续浏览。新缩略图也需要随网站发布；可以用 `node scripts/check-miniprogram-downloads.mjs --thumbnails --wait` 完整验证线上资源。
