# 商品上新流程

适用于给 Hobby Lobby 花色目录批量新增商品。只读取本批素材和项目的当前数据，不需要之前的聊天或旧照片。

## 每次发这一句

> 上传新品：318 1.2L；图片在 `C:\Users\33865\Downloads\318新品`；直接发布。

每批用一个文件夹，只放本次要上的成品图。混合容量分文件夹或明确给出每张图的容量；上传套装时直接注明「319 套装」。不写「直接发布」就只录入本地。已有文件夹路径时，直接读取，不要求把同一批图重新贴进聊天。

## 导入规则

1. **确定本批范围与顺序。** 只读指定目录的图片（PNG、JPG/JPEG、WebP），不递归扫描下载目录。用户明确给的顺序优先，其次按文件名自然顺序（如 `01`、`02`、`10`）；只有附件时按提供顺序。先核对数量、容量及重复图。能从文件名明确判断的不用再问；容量冲突、无法判断是否同款的，只确认有疑问的图。若确认是已录入的同一张图且规格相同，不重复编号；不同容量或明显不同花色不按重复处理。
2. **按现有目录续号。** 以 `src/data/products.json` 为准，用 `src/catalogue-numbering.js` 的 `nextCatalogueCode` 查对应序列最大号，逐件续编。`318 1.2L` 用 `318A-*`，`318 2.0L` 用 `318B-*`，319 单壶用 `319-*`，319 套装用 `319套装-*`。319 的可售容量以该批说明和现有商品规格为准，不能仅凭渲染图文件名猜测。编号写入 `catalogueCode`；新 `productId`、`slug` 和图片路径必须唯一，不能覆盖。旧商品的编号、链接、图片、价格和录入顺序不动。不要把 `scripts/import-318-products.mjs` 当成上新脚本：它会重建现有 318 数据，不适合追加。
3. **按图案归类。** 参照 `src/data/categories.json` 和已有同图案商品，用图案名称和主图案选现有系列；明显是同一套设计的不同配色、容量或壶型放在同系列。套装独立归入 `mixed-set`。按现有商品结构补中英文名称和图片说明；价格、装箱数、体积沿用项目里该型号和容量的设置。记录实际录入时间；「最新上新」由目录按上海时间的近一个自然月自动计算，不另建商品分类。
4. **保留原图，生成目录用图。** 不改、不移动用户提供的原文件。将高清 WebP 和独立的轻量缩略图放到 `public/assets/catalogue/`；列表用缩略图，点开用高清图。保持原比例、颜色及完整壶身，不放大低分辨率源图，不覆盖已有文件。

## 核验和发布

- 导入后核对本批张数、型号和容量、连续编号、系列、图片可解码、数据引用和旧记录未改。纯上新做一轮针对性的目录与编号测试；发布前按 [部署配置](DEPLOYMENT.zh-CN.md) 构建，并验证新商品页与站点地图。无需重测无关的 3D 或滚动功能。
- 用户明确要求发布时，先核对是原 `hobby-lobby-catalog` 仓库和现有 GitHub 登录。按 GitHub `main` → Cloudflare Pages 的原流程提交、推送，保留无关改动，不强推、不另建 Sites 副本。不索取或绕过凭据；遇到认证或权限阻塞就停，说明哪些已录入、哪些还没上线。已有本批提交时直接续做推送或线上核验，不重复导入。
- 只有在线目录、商品页与图片实际可访问时才说「已上线」。完成后只需回报上新数量、编号范围、跳过的重复或待确认项（如有）和发布状态。
